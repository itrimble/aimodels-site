Recipes

Copy-paste starting points. Paths are placeholders (/models/...); swap in your own. Check each tool's --help on your build, because flags change between releases.

Bosgame M5: Linux memory setup

On Linux, keep the BIOS dedicated VRAM small (for example 512 MB) and let the GPU borrow system memory through GTT. A commonly used kernel setting for Strix Halo raises the TTM page limit (4 KiB pages; 27,648,000 pages ≈ 105 GiB):

# /etc/default/grub  (then: sudo update-grub && reboot)
GRUB_CMDLINE_LINUX_DEFAULT="quiet ttm.pages_limit=27648000 ttm.page_pool_size=27648000"

# confirm after reboot
cat /sys/module/ttm/parameters/pages_limit

Reported practical ceiling is about 108 GB; going to ~110 GB caused errors for at least one reviewer. On Windows the GPU share is capped at 96 GB (AMD Variable Graphics Memory).

One box: Qwen3.8 Flash-Next IQ4_XS as an OpenAI-compatible server

./build/bin/llama-server \
  -m /models/unsloth-Qwen3.8-Flash-Next-UD-IQ4_XS/UD-IQ4_XS/Qwen3.8-Flash-Next-UD-IQ4_XS-00001-of-00004.gguf \
  --mmproj /models/unsloth-Qwen3.8-Flash-Next-UD-IQ4_XS/mmproj-BF16.gguf \
  -ngl 99 -c 32768 --jinja \
  --host 127.0.0.1 --port 8080
# point any OpenAI client at http://127.0.0.1:8080/v1

Split GGUFs load from the first shard; llama.cpp finds the rest. Same pattern for GLM-5.3-Flash UD-IQ2_XXS (leave context modest: it is the tightest one-box fit).

Two boxes: llama.cpp RPC

# on box B (worker): expose its GPU over the link (USB4 or 10GbE)
./build/bin/rpc-server -H 0.0.0.0 -p 50052

# on box A (main): load the model across both
./build/bin/llama-server \
  -m /models/ISTA-DASLab-DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ1_M/DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ1_M-00001-of-00006.gguf \
  --mmproj /models/ISTA-DASLab-DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ1_M/mmproj-DeepSeek-V4.1-Flash-1017-BF16.gguf \
  --rpc 10.10.10.2:50052 -ngl 99 -c 16384 --jinja --host 127.0.0.1 --port 8080

rpc-server has no authentication. Only run it on a direct cable or an isolated network segment, never on a LAN you share or the internet.

For the ISTA DeepSeek build, the shared Engram file must be linked as shard 6 before loading (from the ISTA card): ln -s DeepSeek-V4.1-Flash-Engram-IQ4_NL.gguf DeepSeek-V4.1-Flash-1017-GSQ-RCO-IQ1_M-00006-of-00006.gguf. Files fetched before Oct 27 2026 need the card's convert_ds41_upstream.py. Keep the Engram file on fast NVMe; it is paged, not held in memory.

Smaller machines: MoE expert offload

# keep attention on the GPU, push MoE expert tensors to system RAM
./build/bin/llama-server -m model-00001-of-0000N.gguf -ngl 99 \
  -ot ".ffn_.*_exps.=CPU" -c 16384 --host 127.0.0.1 --port 8080

This is what makes Flash-Next or GLM usable on omarchy after its 128 GB RAM upgrade (8 GB RX 6600 XT + system RAM). Expect it to be slow: expert reads come over DDR4.

Ollama and LM Studio

# Ollama: wrap a single-file GGUF
cat > Modelfile <<'EOF'
FROM /models/unsloth-Qwen3.8-27B-UD-Q8_K_XL/Qwen3.8-27B-UD-Q8_K_XL.gguf
PARAMETER num_ctx 32768
EOF
ollama create qwen38-27b-q8 -f Modelfile
ollama run qwen38-27b-q8

# split GGUFs: merge first if your Ollama version won't import shards
llama-gguf-split --merge first-00001-of-00004.gguf merged.gguf

# LM Studio CLI
lms import /models/unsloth-Qwen3.8-27B-UD-Q8_K_XL/Qwen3.8-27B-UD-Q8_K_XL.gguf
lms server start

New architectures (Qwen3.8 Flash-Next, GLM-5.3, DeepSeek V4.1) need a recent llama.cpp; Ollama and LM Studio pick up support later. Mirai, Maya and Strata builds won't load in either.

Builds that need their own engine

  • Qwen3.8-27B Mirai S (alesha-pro): use mirai-s-ada (recommended on the card) or the llama.cpp-mirai-s fork.
  • GLM-5.3-Flash Maya-M (alesha-pro): Project Maya engine plus alesha-pro's GLM ablate patch.
  • Flash-Next GSQ-RCO Strata (alesha-pro): Strata engine; the card's setup script writes the engine flags.

Original safetensors: serve or quantize

# quantize your own GGUF from the BF16 archive copy (example: Qwen3.8-27B)
python llama.cpp/convert_hf_to_gguf.py /models/Qwen-Qwen3.8-27B --outtype bf16 --outfile qwen38-27b-bf16.gguf
./build/bin/llama-quantize qwen38-27b-bf16.gguf qwen38-27b-Q5_K_M.gguf Q5_K_M

The Flash-Next, GLM and DeepSeek originals are 300-500 GB; they're kept as the source of truth, not for running on this fleet.

ComfyUI (image, video, YuE2)

git clone https://github.com/comfyanonymous/ComfyUI && cd ComfyUI

YuE2 (ComfyUI repack): put sheetsage2_bf16.safetensors in models/audio_encoders/ and yue2_3b_bf16.safetensors in models/checkpoints/, then load the official "YuE2: Text to Music" workflow template. MOSS-Image: install the MOSS-Image node from ComfyUI Manager. Wan 2.2 and HunyuanVideo 1.5 have ComfyUI integrations listed on their cards.

Image with Diffusers

pip install "torch>=2.4.0" "transformers>=5.17" git+https://github.com/huggingface/diffusers accelerate pillow
import torch
from diffusers import QwenImage21Pipeline
pipe = QwenImage21Pipeline.from_pretrained("/models/Qwen-Qwen-Image-2.1", torch_dtype=torch.bfloat16)
pipe.enable_model_cpu_offload()   # memory optimisation from the model card

img.save("out.png")

Speech: Whisper, Qwen3-TTS, Fish S2 Pro

# Whisper large-v3-turbo via Transformers (card's route)
pip install --upgrade transformers "datasets[audio]" accelerate
python - <<'EOF'
import torch
from transformers import pipeline
asr = pipeline("automatic-speech-recognition", model="/models/openai-whisper-large-v3-turbo",
               torch_dtype=torch.float16, device_map="auto")
print(asr("meeting.wav", return_timestamps=True)["text"])
EOF

# or whisper.cpp (Metal on Mac, Vulkan on the M5), using its own ggml file
git clone https://github.com/ggml-org/whisper.cpp && cd whisper.cpp
sh ./models/download-ggml-model.sh large-v3-turbo
cmake -B build && cmake --build build -j --config Release
./build/bin/whisper-cli -m models/ggml-large-v3-turbo.bin -f meeting.wav
# Qwen3-TTS voice clone (Base model needs a short reference clip + its transcript)
pip install -U qwen-tts
python - <<'EOF'
import torch, soundfile as sf
from qwen_tts import Qwen3TTSModel
model = Qwen3TTSModel.from_pretrained("/models/Qwen-Qwen3-TTS-12Hz-1.7B-Base",
                                      device_map="cuda:0", dtype=torch.bfloat16)
wavs, sr = model.generate_voice_clone(text="Your weekly security digest is ready.",
    language="English", ref_audio="my_voice.wav", ref_text="Transcript of my_voice.wav")
sf.write("out.wav", wavs[0], sr)
EOF

On Apple silicon use device_map="mps"; on the M5 with ROCm PyTorch, AMD GPUs still appear as cuda. Only clone voices you have permission to use. Fish Audio S2 Pro runs with fish-speech; it is research/non-commercial unless you buy a license.

Extras: embeddings, TTS, image and a coding sidecar

The nine extras live under /models/extras/ on the M5. They are small sidecars, not replacements for the main LLMs.

EmbeddingGemma 2 / bge-small

pip install -U sentence-transformers
python - <<'EOF'
from sentence_transformers import SentenceTransformer
m = SentenceTransformer("/models/extras/embeddinggemma-2")
print(m.encode(["local models stay local"]).shape)
EOF

bge-small-en-v1.5-f16.gguf is the tiny llama.cpp embedding alternative: llama-server -m /models/extras/bge-small-en-v1.5-gguf/bge-small-en-v1.5-f16.gguf --embedding --port 8082.

Kokoro 82M / NeuTTS Air

Kokoro is the fast TTS model; use the Kokoro-TTS-Local project against /models/extras/kokoro-82m. NeuTTS Air is a single 0.5 GB GGUF fallback.

Z-Image Turbo / FLUX.1 schnell

import torch
from diffusers import AutoPipelineForText2Image
pipe = AutoPipelineForText2Image.from_pretrained("/models/extras/z-image-turbo", torch_dtype=torch.bfloat16)
pipe.enable_model_cpu_offload()
img = pipe("isometric illustration of a home lab rack").images[0]

FLUX.1 schnell uses FluxPipeline.from_pretrained("/models/extras/flux1-schnell") and four steps. SeedVR2 is a ComfyUI upscaler; the Qwen-Image Q4_K_M GGUF is a ComfyUI-GGUF asset.

Mellum2.1 12B-A2.5B

llama-server -m /models/extras/mellum21-12b-a2.5b-thinking-q4km/Mellum2.1-12B-A2.5B-Thinking-Q4_K_M.gguf   -ngl 99 -c 32768 --jinja --port 8081
